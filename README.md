# 文图 TextPIC

把 Markdown 笔记自动排版成图文卡片。丢一个 `.md` 进去，出来一组 1080×1440 的卡片：第一张是封面大标题，后面按内容自动分页，公式、代码、表格都能正常显示。适合发小红书、公众号图文、朋友圈九宫格，或者任何需要「一篇笔记 → 一组图」的场合。

## 它解决了什么

市面上的 Markdown 转图片工具（[Madopic](https://github.com/xiaolinbaba/Madopic)、[markdown2png](https://github.com/nicejade/markdown2png) 等）大多是把整篇渲染成一张长图，或者要你手动切。文图的核心是**按卡片实际高度自动分页**：

- 在浏览器里以 1:1 尺寸实测每个内容块的高度，贪心装页，装不下就翻页
- 单个块超过一页时按类型智能切分：段落切在句号处、列表切在条目间、代码按行切（重新做语法高亮，不会切断高亮标签）、表格切行并重复表头
- 可用高度是用一张真实尺寸的「标尺卡片」量出来的，页眉页脚和各主题不同的内边距都会自动算进去
- **「标题不留在页尾」是个开关**：打开时标题会跟着正文翻到下一页，排版更整齐但前一页会空一块；关掉就优先塞满每一页。这个取舍没有标准答案，自己按内容选

配套还有 KaTeX 公式（`$...$`、`$$...$$`，也认 `\(...\)`/`\[...\]`，以及 ChatGPT 等大模型更常用的双反斜杠写法 `\\(...\\)`/`\\[...\\]`）、6 套模板、AI 文案生成。Chrome 扩展里还内置了一个可选的小红书创作台自动填表功能（图片和文案自动填好，发布按钮留给你自己点）。

编辑器还提供面向发布场景的三组增强能力：

- **水印策略**：文字或 Logo 水印，可调透明度、九宫格位置、旋转、大小与文字颜色，并分别保存全局、小红书、公众号和朋友圈策略
- **广告推广页**：在封面后或图文末尾插入独立推广卡片，内置账号介绍、产品推广、课程推广模板，标题、介绍、CTA、二维码都可修改
- **小红书文案独立编辑**：不调用 AI 也能手动填写；标题候选可新增、删除和修改，正文与标签也可单独维护

## 三种用法

### 1. Chrome 扩展（推荐）

跑在你已登录的 Chrome 里，不用处理 cookie，也不用额外下浏览器。

```bash
pnpm install
pnpm build:ext
```

然后打开 Chrome → 扩展程序 → 打开右上角「开发者模式」→「加载已解压的扩展程序」→ 选 `dist-extension` 目录。

点扩展图标开侧边栏，粘贴或打开 `.md`，选模板，然后：

- **导出 PNG** — 打包成 zip 下载，拿去发哪个平台都行
- **一键填入小红书 / 抖音** — 自动打开对应平台的创作者中心（`creator.xiaohongshu.com` / `creator.douyin.com` 图文发布页），把图片塞进上传框，填好标题、正文、话题，然后**停在发布按钮前**，最后一步由你确认

填表进度显示在创作平台页面右侧的抽屉里：每一步成功/失败一目了然，可以收成页面边缘的一个小把手，把手上的圆点仍显示状态（黄=进行中、绿=完成、红=有步骤失败）。点「重新填写」只会重填文字，不会把图片再传一遍。

### 2. 纯网页版

不想装扩展就直接跑，功能一样，只是没有「填入创作台」这一项。

```bash
pnpm dev
```

### 3. 命令行批量出图

适合一次处理一个文件夹的笔记。需要先装一次浏览器内核：

```bash
pnpm exec playwright install chromium
```

```bash
pnpm build
pnpm cli build 笔记.md --theme grid --out ./out
pnpm cli build ./我的笔记目录 --theme ink --copy
pnpm cli build 笔记.md --font-scale 0.9 --no-keep-heading   # 字号再小一点、每页塞满
pnpm cli build 笔记.md --image-height 560                    # 压低配图高度，让图和正文同页
pnpm cli themes
```

`--copy` 会额外生成 `copy.txt`（标题 / 正文 / 标签），需要设好环境变量：

```bash
export TEXTPIC_API_KEY=sk-xxx
export TEXTPIC_BASE_URL=https://api.deepseek.com/v1
export TEXTPIC_MODEL=deepseek-chat
```

## 写笔记的约定

````markdown
---
title: 三分钟搞懂梯度下降        # 封面大标题，不写就取第一个 # 标题
subtitle: 从山顶找路下山的直觉出发   # 封面副标题，不写就取第一段
badge: 机器学习入门              # 封面左上角的小标签
author: 你的署名                # 每页页脚显示的名字
tags: 机器学习, 学习笔记          # 给 AI 生成标签时做参考
theme: grid                    # 打开文件时自动选中这套模板
---

## 正文标题

行内公式 $E = mc^2$，块级公式：

$$
\theta_{t+1} = \theta_t - \alpha \nabla J(\theta_t)
$$

---

`---` 会强制从这里翻到下一页。也可以写 `<!-- page -->`。
````

frontmatter 全部可选，直接丢一篇普通 Markdown 也能用——连标题都不用写，点一下「AI 生成」，标题、副标题、分类标签会自动补进 frontmatter 里（原有字段不会被覆盖）。`author` 也可以不写，在「设置」里填一次「默认署名」，之后每篇笔记没写 author 就自动用这个兜底。

连 Markdown 格式都不想写？粘贴一段没有标题、没有列表的大白话文本，点「AI 排版」，会自动拆小节、加标题、把并列的点改成列表——frontmatter 不受影响，只重排正文。

正文读着「AI 味」太重，点「AI 去味」重写一遍。上面那排**「AI 文风」三档**决定用哪种路子：

| 档位 | 做法 | 特点 |
| --- | --- | --- |
| ① 机翻回译 | 删光「首先/其次/然后/总之」这类强逻辑词，模拟机器翻译成英文再译回中文 | 连接词最干净，但会留下翻译腔：主语补得过全、措辞偏书面 |
| ② 提示词法 | 要求模型提高词汇丰富度、内容不可预测度、句子长度的波动幅度 | 最像「写作者本人」，代价是模型容易顺手加戏，事实和数字要核 |
| ③ 人设法 | 让模型扮演一个文化程度不高、说话逻辑性偏弱的大学生 | 几乎不可能被认成 AI，但信息密度掉得厉害，技术类内容会显得不专业 |

这一档是**正文改写和小红书文案共用的**：选定之后，「AI 去味」按这个腔调重写正文，右边「AI 生成」也按同一个腔调写文案，不会出现图上是一个调子、配套文案又是另一个调子。三档都有同一条硬约束——只改「话怎么说」，标题层级、列表、代码块、公式原样保留，事实和数字一字不许动。

公式写错了会实时标出来（预览区上方会出现一条"公式格式有误"的提示，附上具体报错原因），点旁边的「AI 修复」能让 AI 尝试改好语法，改完自动换回原文对应位置——不用等导出以后才在图片里发现一个刺眼的红色报错框。

侧边栏就那么点地方，写长笔记、贴图片不够用——「全屏编辑」会在新标签页里打开同一个应用（Chrome 插件里是真正新开一个标签页，不是在侧边栏里弹个层）。这个新标签页布局参考了 [Madopic](https://github.com/xiaolinbaba/Madopic)，三栏：

- **左栏**：编辑器，顶部带一条工具栏——粗体/斜体/删除线、标题、引用、行内代码、有序/无序列表、链接、插入图片、表格、分页线，点了就在光标处插入或包住选中的文字；底部是「AI 文风」三档和 AI 排版 / AI 去味 / AI 封面
- **中栏**：预览在上，样式 / 水印 / 广告页收在下面一个标签窗口里
- **右栏**：「小红书 | 抖音」两个文案标签页，各自按平台的写法和上限生成、编辑，底部就是该平台的「一键填入」按钮；整栏可以收起成一条竖条

已经有小红书文案时，抖音版会直接拿那份文案改写，不再把笔记正文重新发给模型。全屏编辑页右上角的 × 会关掉这个标签页并打开侧边栏；从侧边栏进入全屏编辑时，侧边栏会自动关闭。界面支持浅色 / 深色，顶栏可切换。

三栏默认等宽，**列之间可以拖着调宽度，中栏的预览和设置面板之间也能上下拖**，双击分隔条恢复默认，比例会记住。每一列都锁在一屏高度内，需要滚动的是列里那块内容而不是整个页面——功能面板做成标签页也是为了这个：以前每加一个功能就往列底追加一块，整列越来越长，最后逼着整页上下滚。

标题和标签是**可就地编辑的气泡**：鼠标移上去露出绿色铅笔，点铅笔或双击气泡直接改，回车提交、Esc 撤销；「＋」气泡点一下原地变输入框，加标签时回车可以连着加好几个。

图片除了工具栏那个按钮，也能直接拖进编辑框，或者复制了图直接 Ctrl+V 粘贴（同样参考 Madopic 的剪贴板粘图）。图片会转成 data URL 嵌进 Markdown，过大的会先自动压缩再嵌入。侧边栏本身空间太小，没放这套工具栏，只保留了「AI 排版」和跳到全屏编辑的入口。

侧边栏和全屏编辑标签页是实时互通的：不管在哪边改笔记，另一边只要没在打字，几乎立刻就能看到最新内容，不需要手动导入或者刷新。

## 带配图的笔记

笔记里的图片如果是 `figures/xxx.svg` 这种相对路径，单选一个 `.md` 是读不到的——浏览器拿不到它旁边的文件。点顶栏的「**打开文件夹**」，选中笔记所在的整个目录，md 和图片就会一起读进来。

关键设计是**图片不写回正文**：笔记里始终保留作者写的那个短路径，图片本体单独存一张表，只在渲染卡片时才换成 data URL。一张 SVG 内联成 base64 就是几万个字符，写回正文会让编辑框里全是乱码、存储体积翻十几倍、发给 AI 的内容也被 base64 淹掉（实测一篇带图笔记，编辑框会从 5 千字符涨到 15 万）。粘贴、拖入的图也走同一套。

- 一个文件夹里有多篇笔记时，上面会出现一个下拉框，切换笔记复用同一份图库，不用重复读
- 图库会单独存一份，刷新后图片照常显示；超过 3MB 就不存了（网页版 localStorage 只有几 MB，写爆会连累所有设置），图还在内存里能用，只是下次打开要重新选一次文件夹
- 找图是逐级放宽的：先按完整相对路径匹配，再按路径后缀，最后按文件名唯一匹配

如果笔记用 `<picture>` 给了手机版和电脑版两套图，会多出一个「**配图版本**」开关。卡片是 1080×1440 的竖版，两套图的差别很大：手机版通常是竖长图（占满版面、细节大，但一张图容易独占一整页），电脑版是宽扁图（占高度小，能和正文挤在同一张卡里，卡片数更少）。`<picture>` 会被拍平成单个 `<img>`——卡片尺寸固定，用不着响应式候选，而且导出用的 html-to-image 是克隆 DOM 再序列化，`<picture>/<source>` 容易掉图。

发给 AI 之前还会再兜一道底：把长图片地址换成 `pm-img-1` 这样的短占位符，返回后换回来。正文里现在本来就没有 base64 了，但手动贴进来的 data URL 仍可能很长——早先版本把图片内联进正文时，实测发出去的前 6000 字里 **97% 是 base64**，模型几乎看不到正文。图片的位置和 alt 照常保留，模型知道「这里有张图」。

样式面板里的「**图片高度**」控制图片的高度上限（240~1180px，卡片坐标系内的绝对像素，不跟字号缩放）。这一项比看上去重要：**图片是原子块，切不开**——段落能从句号断、列表能按条目断，但图没法劈成两半，所以一张比整页内容区（约 1220px）还高的竖图必然把那页撑爆。调小它是让竖图和正文挤进同一页最直接的办法。

## AI 文案

侧边栏点「设置」，选一个服务商填 Key 即可。走的是 OpenAI 兼容接口，内置了 DeepSeek / Kimi / 通义 / 智谱 / OpenAI 的地址预设，也可以填任意自定义 `base_url`。

Key 只存在本机浏览器（扩展里是 `chrome.storage.local`），不会上传到别处。扩展会在你保存设置时申请对应域名的访问权限。

这一项内置的是**小红书文案规则**（标题 ≤ 20 字、正文 ≤ 1000 字、标签 ≤ 10 个，正文前两行交代清楚这篇能解决什么问题），因为那是目前唯一有明确、可执行规则的平台。发别的地方可以把生成结果拿去自己改。

文案的腔调跟着编辑区那排「AI 文风」走（① 机翻回译 / ② 提示词法 / ③ 人设法），和正文改写共用同一档，保证图文一致。

### 少花点 token

几个 AI 功能是各自独立的请求，点一遍「排版 → 去味 → 生成文案」，同一篇笔记会被完整发三次。所以做了几件事：

- **选中一段再点**「AI 排版 / AI 去味」，就只发这一段（选中 ≥30 字才生效）。长笔记通常只想修某一段，实测选中 500 字、全文 5000 字时只发 500 字，省九成；顺带也避免模型顺手改动别处
- **「AI 封面」只发正文开头 700 字**，因为封面只需要知道这篇讲什么。要是已经生成过文案，里面本来就带着封面，直接套用，**一次请求都不发**
- **会话内结果缓存**：同样的输入不重复请求，挡住手滑双击。内容改一个字缓存就失效，不会拿到过期结果
- **每种调用都设了输出上限**：封面 200、修公式 400、文案 1400；改写类按输入长度动态给（输出和输入等长），留足余量免得长文结尾被截断

设置面板底部会显示本次会话发了多少字符、多少次请求、缓存省下多少。

同一次生成会顺带产出封面用的标题 / 副标题 / 分类标签，直接回写进笔记的 frontmatter——这是为了让「贴一段没有标题的原始内容 → 点一下 AI 生成 → 直接导出图片」这条路径尽量少手动编辑。

## 代码结构

```
src/core/         渲染引擎，不依赖 React，三条使用路径共用
  markdown.ts       解析 + 切块
  math.ts           KaTeX 插件和定界符归一化
  paginate.ts       测高 + 贪心装页
  split.ts          超长块的切分策略
  themes.ts         模板元信息
  card.ts           卡片 HTML 生成
  card.css          全部模板样式
  images.ts         相对图片路径 → data URL（只在渲染时换算）
  export.ts         PNG / zip 导出
  ai.ts             文案生成、去 AI 味、封面，含缓存和用量统计
src/app/          React 界面，网页版和扩展侧边栏共用
extension/        MV3 manifest、background、小红书创作台 content script
cli/              命令行入口
scripts/          扩展打包和图标生成
```

## 已知限制

- **图片尺寸目前固定 1080×1440**（小红书推荐比例，公众号/朋友圈同样合适）。要适配其他平台的比例，改 `src/core/types.ts` 里的 `CARD_W`/`CARD_H` 即可，主题样式是用相对单位写的，理论上能跟着适配，但没有针对别的尺寸测试过。
- **创作平台的选择器可能失效。** 平台前端改版后，自动填表会有某一步失败。选择器集中在 [`extension/content-xhs.ts`](extension/content-xhs.ts) 和 [`extension/content-douyin.ts`](extension/content-douyin.ts) 顶部的 `SELECTORS` 里，页面右侧抽屉会显示是哪一步断的，对着改就行。**抖音这份选择器没有在真实账号上跑过**，第一次用时大概率需要校准。
- **话题标签不保证全部关联成功。** 小红书的 `#话题` 需要从下拉列表里选中才算真话题，纯文本的 `#` 不算。脚本会尝试等下拉出现并选第一项，失败的会退化成纯文本，状态面板里会告诉你成功了几个。
- **单篇最多 18 张图**，超了会截断并提示你拆成两篇。
- 浏览器自动化发帖处在小红书用户协议的灰色地带。这个工具只操作你自己已登录的浏览器、且不会替你点发布，但仍建议只用于自己的账号、控制发布频率。
